# 油品配送计划 · 罐车分舱装载与站间退油

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 判定层冒烟：`npx vite-node scripts/smoke.ts`（15 项）、`npx vite-node scripts/smoke-store.ts`（20 项）

数据默认保存在浏览器 localStorage（键 `hxwlfront-19-oil-delivery-v2`），可在页面上"重置演示数据"。

## 业务规则

1. **趟次登记**：每趟登记车辆（车牌）、舱位、油品、载重、到站顺序。
2. **整趟退回**：同舱只能装同品；任一舱跨品、超额定载重，或到站顺序缺失/越界，整趟退回，页面保留全部输入并列出退回原因。
3. **站方退油**：只能回装"原品空舱"；余量只按该舱在本站实际卸空的同品载量计算，不压占后续站点舱容；超出余量的部分自动转"待处理"，可登记结清说明。
4. **发车冻结**：发车后舱位与到站顺序冻结；运输中只能登记到站卸油与站方退油。
5. **重开留痕**：冻结后调整必须先"重开"并填写原因；舱位计划、到站顺序、车牌的每次调整都保留 旧值 → 新值 与原因，被替代的装载行作废（void）但保留修订链（`supersedes`、已卸量沿链继承）。
6. **重开核对**：再次发车前按"舱 × 油品"做物理平衡核对（实装 − 已卸 + 回装 − 挂账 = 舱存，须与新计划对应），冲突清单列出 **车牌、舱号、油品与差额（吨）**；存在冲突或未结清待处理项时禁止发车。整舱油品已全部卸净时可"作废"空计划行。

## 分层结构（资料 / 判定 / 存储 / 页面分开）

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 资料 | `src/types.ts`、`src/data/catalog.ts` | 领域模型；油品、站点、罐车分舱资料与种子数据 |
| 判定 | `src/domain/rules.ts` | 纯函数：装载校验、退油余量与回装规划、重开冲突核对、冻结判定（不碰存储与界面） |
| 存储 | `src/stores/delivery.ts` | Pinia store：状态编排、localStorage 持久化、动作结果返回 |
| 页面 | `src/App.vue`、`src/components/*.vue` | 趟次登记表单、趟次卡片、到站卸油/退油/重开修订对话框 |

## 页面说明

- 左侧：登记配送趟次（车辆选择、到站顺序上下移、分舱装载表，实时显示各舱额定/已配/限装与预检错误）。
- 右侧：趟次列表与筛选（状态、站点、只看重开冲突），卡片含到站顺序、舱位装载、退油回装、待处理、修订时间线、冲突表。
- 顶部指标：趟次、运输中、在途载重、待处理油品吨数、重开待复核数。
