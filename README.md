# 油品配送计划 · 罐车分舱装载与站间退油

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 规则核验：`npm run check:rules`（判定层 13 项）、`npm run check:store`（端到端 30 项）、`npm run check:render`（SSR 渲染冒烟）

数据保存在浏览器 localStorage（键 `hxwlfront-19-oil-delivery-v2`），首次打开带 3 个示范趟次与 1 笔待处理退油。

## 业务规则

1. **分舱登记**：每趟登记车牌、舱号、油品、载重与到站顺序；同舱多行登记自动合并。
2. **整趟退回**：同舱跨品混装、任一舱超核定载重、舱位不属于所选车辆时，整趟校验失败且不落库，表单输入原样保留。
3. **站间退油**：站方退油只能回原品舱，空舱优先、余量舱其次，最多入到核定载重；本站卸空腾出的舱位可接退油；入不下的数量转"待处理台账"，不向其他品舱借容、不压占后续站点。
4. **发车冻结**：发车后舱位油品与到站顺序冻结；载重调整随时可做但必须填原因，自动留旧值/新值/差额；改油品、调顺序必须先"重开行程"并填原因；已有交付/退油记录的舱不允许改品。
5. **站务重开**：可凭原因重开当前站补录交付/退油，留痕"到站重开"。
6. **核对**：重开后的配送、舱位、退油、修订统一按 车牌 → 舱号 → 油品 核对，列出应有、实际与差额；超核定、负库存、跨品作业、修订与实际作业不符、未办结待处理、已到站欠交都会进入冲突表。

## 分层结构

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 资料 | `src/data/catalog.ts`、`src/data/seed.ts` | 油品、车辆/分舱核定载重、油站主数据与示范趟次 |
| 判定 | `src/logic/rules.ts`、`src/logic/helpers.ts` | 纯函数规则：装载/到站/交付/退油校验、在舱量推算、整趟核对 |
| 存储 | `src/store/trips.ts` | Pinia store：趟次 CRUD、发车、交付、退油、修订、重开、待处理办结、localStorage 持久化 |
| 页面 | `src/App.vue`、`src/components/*` | 登记表单、趟次卡片（操作/留痕/冲突）、待处理台账与指标筛选 |

类型统一定义在 `src/types.ts`。页面与 store 不自行解释业务规则，全部调用判定层。
